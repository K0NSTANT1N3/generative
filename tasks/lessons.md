# Project-selection lessons

- A proposed generative project must have a concrete application and target property, not only valid or novel outputs.
- When the user requires direct prior work, verify a project that actually generates or optimizes the same object for the same property before recommending it. A property predictor, analytical structure-inference model or generator of the binding protein is not an equivalent precedent.
- Distinguish predictor-guided mutation/search from training a conditional generator, and predicted improvements from experimental usefulness.
- Keep follow-up research bounded and deliver focused, usable findings promptly when the user prioritizes speed.
- Define an aptamer project with a named target protein, exact sequence data, generated object, target property, and evaluation limits; generic references to candidates or one target are insufficient.
- Treat easy training on one free T4/P100, about four GPU-hours including evaluation, as a hard gate before mentioning project ideas. Check primary-source compute first; reject large-compute projects rather than proposing pretrained inference or unverified fine-tuning as substitutes. Unknown compute does not establish eligibility.
