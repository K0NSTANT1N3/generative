# Additional microbial/NP generation coverage audit

This addendum covers two relevant 2026 discoveries and the scope check requested against Sakano et al.'s 2026 review. Primary records checked: the arXiv HTML/PDF landing metadata, official GitHub repositories and configs, and the review's paper table/text. Where the source did not state an item, it is marked not reported; source accessibility is not treated as proof of a permissive data license.

| **2. Goal and generation/conditioning** | SpaceGFN explicitly constructs chemical spaces from building blocks plus reaction rules, then trains a GFlowNet to sample high-reward molecules. Its two NP-adjacent Discovery demonstrations are a **pseudo-natural-product architecture space** and an **evolution-inspired space** recombining endogenous-metabolite fragments with enzyme-consistent transformations. These are conditioned by the chosen space grammar and selected scoring/reward signals; abstract reports predicted metabolic/toxicology profiles and docking enrichment, not experimentally measured antibacterial function. This is not microbial-NP-data training or antibiotic-specific inverse design. | Pretrains NP-focused autoregressive models and **unconditionally** samples pseudo-NP SMILES; generation is not conditioned on a named activity. Separate property prediction tasks cover cyclic peptide membrane permeability, taste, and general anti-cancer activity. The study is primarily a model/tokenizer comparison, not a function-directed antibiotic designer. |
| **3. Model and size** | Flow-based **GFlowNet** (trajectory-balance default in official config) over discrete building-block/reaction states. Repo config sets forward batch 64, 5,000 training steps, 2-layer policy networks with 128- or 256-wide hidden layers. Total parameter count not reported. | Decoder-only GPT-2-style Transformer, Mamba, and Mamba-2; eight tokenizers across random/scaffold splits, 48 configurations total. Paper reports **8.96M–69.7M parameters** across configurations. |
| **4. Training data and exact access** | Space definition uses external building-block/reaction sources: pseudo-NP blocks are attributed to Waldmann et al.; Evo blocks to HMDB; enzyme-consistent reaction templates to RetroBioCat. The official repo says it supplies processing workflows, but its checked `data/` directory has only 1YND initial/target examples and templates, not the paper's full discovery-space block/reaction datasets. Exact sample counts, file sizes, formats, and direct source URLs for the paper's PNP/Evo inputs were not established from accessible primary material. | Paper confirms **1,030,273 curated NP SMILES** from SuperNatural 3.0, COCONUT and LOTUS, after duplicate removal, RDKit validation, standardization/canonicalization, charge neutralization and tautomer canonicalization. 80/10/10 random and scaffold splits. Official repo says these data are in GitHub `data/1M_NPs/` as split text files (`train/val/test`, SMILES); datasets and generated outputs are immediately browsable/downloadable without an application. Exact byte sizes not exposed in inspected GitHub pages; no explicit data license was located in the repo. The data derive from COCONUT CC0 plus LOTUS/SuperNatural sources, so do **not** assume the merged curated file itself is uniformly CC0 without a license statement. |

Pretrained model links exist on Hugging Face, but license and weight sizes were not independently confirmed here. The article says some pretraining workflows require a Weights & Biases API key; this is an experiment-logging credential, not a data-use form, but it complicates a clean no-setup reproduction. |
| **6. Compute** | Exact hardware and wall time/GPU-hours are **not reported in the sources accessible in this pass**. Official config reports 5,000 GFlowNet updates, batch 64, float32, `n_samples=10000`, reaction_step 2; it does not report epoch count. No credible total GPU-hour estimate can be formed from steps alone because oracle calls / docking and construction/pruning of the chemical-space environment can dominate. A small policy net suggests the neural update component may fit a T4, but that is not equivalent to reproducing total pipeline compute. Setup is not a <5-minute path: README requires creating a Python 3.12.9 conda environment and running a dependency-install shell script. | **Paper-confirmed:** all pretraining was on A100 GPUs; each model took “hours to a week” (paper range), but exact per-run times/hardware count are not reported. **Repo-confirmed:** batch size 32, fixed sequence length 512, up to 150 epochs with early stopping after 5 validation epochs without improvement; GPT defaults to 8 layers, width 256, model-specific head count; optimizer uses SAM over Adam. Thus no verified T4-under-4h training route: 1M examples at batch 32 imply about 25,800 minibatches/epoch before padding/invalid-batch skips, up to 3.86M minibatches over 150 epochs, and the paper's actual A100 runs span hours to a week. A shorter pilot is possible but is not replication. The repository Dockerfile/cluster scripts and Mamba CUDA dependencies plus W&B make <5-minute setup implausible. |

## Boundary / coverage findings

- The 2026 *Nature Machine Intelligence* paper **“Pretraining a foundation model for small-molecule natural products”** (NaFM; DOI [10.1038/s42256-026-01226-8](https://doi.org/10.1038/s42256-026-01226-8)) is **not a generative-model row** based on the primary abstract/article description found: it is a natural-product representation/foundation model for downstream mining/classification/regression, with contrastive and masked-graph pretraining. The repository/benchmark provides embeddings; no de novo structure-generation objective was found. Do not conflate this NaFM with the distinct arXiv NPCLM Mamba/Mamba-2 work above.
- Sakano et al.'s 2026 review, **“Chemical language models for natural product discovery”**, *Natural Product Reports* (DOI [10.1039/D6NP00002A](https://doi.org/10.1039/D6NP00002A)), explicitly catalogs Tay et al. (LSTM), NPGPT (decoder Transformer), and NP-VAE as NP-like molecule generators. It discusses NIMO and S4 in surrounding text but its generator table omits them; those two remain included in the main NP audit because their primary papers explicitly generate NP-like structures. The review's reference scan did not surface a different clearly NP-focused molecular-generation paper that changes that list. SpaceGFN is an additional 2026 framework with NP-like / evolutionary chemical-space demonstrations, but is a programmable-space and property-biased GFlowNet framework rather than an NP-trained model.
- **EPOSMol** (Tehemton Khairabadi and Vishal Pagidipally, Quantiphi; GEM workshop, ICLR 2025), [paper](https://openreview.net/pdf?id=D4Nj9PWtMz), is an adjacent inverse-design framework rather than a microbial-NP generator. It uses a 12M-parameter NP-VAE, with a 256-dimensional latent representation, then evolutionary policy-gradient search conditioned on a target oracle/reward (e.g. PDK1 docking affinity and QED; separately NP-likeness/LogP/SA/QED losses guide the latent space). The paper says the model was retrained for 100 epochs / 36 hours on **four Tesla T4 GPUs** (144 GPU-hours) using ZINC250k, DrugBank, and 50,000 custom compounds resembling underrepresented DrugBank structures; the custom 50k corpus is not described as NP-only. The study reports 36,420 generated and 22,245 unique structures in an extended run, but 14,175 duplicates and explicitly says future work should improve sampling efficiency. It reports Vina scores/hit rate, QED, and scaffold diversity; these are computational predictions, not wet-lab outcomes, and the authors note the pretrained upstream weights poorly generated structures outside their original training set. EPOSMol code was not located. Underlying [NP-VAE repository](https://github.com/toshikiochiai/NPVAE) has a custom license: academic use free, commercial permission required; its original project dataset is partly unpublished/restricted. The EPOSMol paper does not provide corpus byte sizes or state a license for its mixed/custom training data. DrugBank access is licensed/restricted rather than an immediate no-form download; hence it fails the user's data criterion.
- **ShEPhERD** (Keir Adams, Kento Abeywardane, Jenna Fromer, Connor W. Coley; MIT, ICLR 2025 oral), [paper](https://arxiv.org/abs/2411.04130), is a general 3D bioisosteric ligand generator with a natural-product ligand-hopping demonstration, not a model trained specifically on microbial natural products. Its SE(3)-equivariant diffusion model jointly generates 3D molecular structure and shape/electrostatic/pharmacophore representations; conditioning is an explicit 3D interaction profile. Training sets are GDB-17 and MOSES-aq, not NPs; the GitHub README says each full dataset is <10 GB and obtainable via Dropbox, but gives no sample counts/license in the inspected source. [Official code](https://github.com/coleygroup/shepherd) is MIT. Authors report training on V100 32GB: each of P(x1,x2), P(x1,x3), P(x1,x3,x4) used two GPUs for ~2 weeks, while P(x1,x4) used one GPU for ~2 weeks; effective batch ~48 molecules. This is far outside the T4/4-hour budget. Sampling 10 independent molecules takes 3–4 minutes on a V100 at T=400; CPU is 5–10 minutes/sample. They describe DDPM sampling and memory-intensive E3NN modules as speed limitations, and defer acceleration. Evaluation uses validity, relaxed RMSD/3D similarity and profile similarity; the natural-product ligand-hopping demonstration is not proof of antibacterial activity. Training-data link is Dropbox, no license confirmed in repository, and full evaluations live in a separate repo.
- Historical scope note: Merk et al.'s 2018 [RXR modulator generator](https://doi.org/10.1038/s42004-018-0068-1) is older than the requested window but is relevant prior art: an LSTM was fine-tuned on six natural-product RXR-agonist templates and produced four synthesized candidates, two reported as isofunctional modulators. It is a narrow template-conditioned drug-design study, not microbial NP generation.
