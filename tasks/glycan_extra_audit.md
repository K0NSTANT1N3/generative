# GlyContact and SweetFold follow-up audit

Sources opened 2026-10-23: [Nature Communications article](https://www.nature.com/articles/s41467-025-67590-y), [PMC full text](https://pmc.ncbi.nlm.nih.gov/articles/PMC12706034/), [official GlyContact repo](https://github.com/BojarLab/glycontact), [SweetFold repo](https://github.com/Keshav-Sundar-4/SweetFold), [SweetFold training instructions](https://github.com/Keshav-Sundar-4/SweetFold/tree/main/instructions/training), [Zenodo 21105358 API metadata](https://zenodo.org/api/records/21105358). Dataset byte/license metadata for SweetFold are from the locally retrieved Zenodo API JSON. Both metrics CSVs were fetched and inspected: the Phase I log spans epochs 0–70, Phase II spans epochs 0–23, and neither contains a time/duration/elapsed-time field.

## GlyContact / von Mises-SweetNet

| Required field | Findings |
|---|---|
| Citation | Luc Thomès, Roman Joeres, Zeynep Akdeniz, Daniel Bojar, “GlyContact analyzes glycan 3D structures at scale,” *Nature Communications* 16, 11136 (2025), DOI [10.1038/s41467-025-67590-y](https://doi.org/10.1038/s41467-025-67590-y). University of Lille, University of Gothenburg/Wallenberg Centre, Saarland University. |
| Goal / generated output | GlyContact itself is a retrieval/analysis package, not a generator of glycan topology. Its associated von Mises-SweetNet model is conditional on an input glycan sequence and predicts distributions over each glycosidic torsion angle plus SASA/flexibility attributes. It samples torsion-angle values for Ramachandran plots/ensemble statistics, but **does not jointly sample correlated angles or output a complete, physically valid 3D coordinate conformer**. Thus it is conformational-attribute generation, not full 3D structure generation, and not functional glycan design. |
| Model family / size | SweetNet-style graph neural network changed to three GIN layers (two 128-hidden linear transforms per layer, ReLU, batch norm, 30% dropout); angle heads predict up to 5-component von Mises mixtures for φ/ψ/ω, additional regression heads for SASA/flexibility. Exact parameter count not stated. |
| Data | GlycoShape MD structures: 717 glycans with accessible PDBs, 6,911 conformer structures; data source is GlycoShape API. Model training on 6,911 conformers; train/validation split 70/30 by glycan sequence, no conformers of a glycan shared between splits. UniLectin3D data: 1,437 processed lectin-glycan PDB complexes used for analysis and stored in repo. The separate lectin-prediction benchmark uses 368 glycans, 2,097 proteins, 354,958 glycan-binding z-scores (but this is not the torsion model’s training dataset). |
| Access / license / size | GlyContact package/repo MIT ([license](https://github.com/BojarLab/glycontact/blob/main/LICENSE)); paper CC BY 4.0. GlycoShape is described by paper as open-access and fetched via public API, but a dataset-wide license and total download size are not stated in the article. UniLectin3D-derived structures are stored in the repo; separate license for third-party structures should not be inferred from MIT code license. Repo files include data assets but there is no paper-reported aggregate byte size. No application/login gate found for article/repo/API. |
| Training compute | For the torsion/property model, paper reports PyTorch 2.5.1/PyG 2.6.0, one NVIDIA GeForce RTX 4060, Adam and linear warm-up/cosine annealing. It does **not report epochs, batch size, elapsed time or GPU-hours** in accessible article/repo sources. Do not transfer the separate LectinOracle_struct recipe (batch 128, up to 150 epochs) to this model. 6,911 conformers and a modest 3×128 GIN suggest a T4 baseline is plausible under 4 hours, but that is a qualitative estimate only; exact timing cannot be estimated confidently without epochs/batch or an observed log. |
| Code / license | Code is released at [BojarLab/glycontact](https://github.com/BojarLab/glycontact), MIT. README shows `pip install glycontact`; optional ML dependencies are `glycontact[ml]`. |
| Evaluation / novelty | Torsion angular RMSE on held-out glycan sequences; report gives unseen-glycan errors about 7° φ, 9° ψ, 10° ω, compared to mono-/disaccharide means/medians and single-most-frequent-conformer SweetNet baseline. Also weighted RMSE for SASA/flexibility. Authors sampled predicted distributions to compare Ramachandran plots. This is held-out structural attribute prediction; no generated full-conformer physical validity metric or training near-duplicate audit. Split by sequence avoids same-glycan conformer leakage. |
| Limitations | Authors explicitly state φ/ψ/ω angle-angle dependencies are not learned, so full glycan conformational ensemble generation remains future work; they caution MD-derived trends may not generalize to glycans attached to proteins, recommend more X-ray structures, and note quantitative state distributions need experimental validation. GlyContact does not remediate/correct wrong input 3D structures. Most glycan structures (all conformers) process in <0.1 seconds on an ordinary laptop; structure extraction/attribute routines take under a second in reported workflows, but that is not a per-sample generation benchmark. |

**How to classify it for the project comparison:** include it as a 2025 conformational-property model with stochastic angle sampling, but do not describe it as an end-to-end glycan 3D generator. It does not supply the missing correlated torsion sampling / coordinate construction required to generate a realistic conformer ensemble.

## SweetFold license and training-source follow-up

- SweetFold repo page does not expose a `LICENSE` file or license badge; classify **code license: no license stated** unless an explicit upstream file is found. Its README documents the Boltz-1x/SweetFold code and training workflow, but does not itself grant a code license.
- Zenodo record [10.5281/zenodo.21105358](https://doi.org/10.5281/zenodo.21105358) API metadata specifies **CC BY 4.0** for the record. This resolves the prior uncertainty about dataset license. It is large: Phase I final dataset ZIP 28,794,135 bytes; Phase II final dataset ZIP 2,931,068,829 bytes; Phase II raw dataset 3,615,648,742 bytes; raw PDB data 5,667,315,314 bytes; GlycoShape archive 475,517,349 bytes. Other benchmark ZIPs and two metrics CSVs are also included. No login or application gate in Zenodo record/API.
- Official repo training configuration (`instructions/training/full.yaml`) says four GPU devices, FP32, gradient accumulation 32, `max_epochs: -1`, 15,000 samples per epoch, batch size 1, four data-loader workers, and a pretrained Boltz-1 checkpoint path; training README instructs installing Boltz 1.0.0 and replacing its `boltz` source with SweetFold’s modified folder. These are repo settings, not a disclosed effective epoch count. Paper had H100 hardware per earlier manuscript audit; exact GPU-hours/wall-clock remain **not reported** from public paper/config as reviewed. This is plainly far outside the 4-hour T4 target for full training.
- Two Zenodo metric logs are tiny and present: `Logs_S1_Phase_I_Metrics.csv` (50,098 bytes; 213 rows, epochs 0–70) and `Logs_S2_Phase_II_Metrics.csv` (253,183 bytes; 396 rows, epochs 0–23). Both contain loss and validation metrics but no elapsed-time/duration columns, so they do not establish GPU-hours. The Phase II dataset itself is multi-GB.

## Corrections to shared glycan audit notes

The SweetNet paper’s authors are **Rebekka Burkholz, John Quackenbush, and Daniel Bojar** (not the earlier short citation “Daniel Bojar, Roman Burkholz”). Its reported hardware is a **NVIDIA Tesla K80**; no paper training wall-time/GPU-hours. This is a 2021 baseline and is prediction/representation learning, not generation. Update the main audit row accordingly.

Root-checked Zenodo records also resolve these dataset license/size values in the main audit:

- GlycoBART record [10.5281/zenodo.15741423](https://doi.org/10.5281/zenodo.15741423): license **CC BY 4.0**; `dataset.xlsx` 1,509,745,314 bytes and `glycans_antennae.csv` 807,866 bytes. Correct the old `1.5 GB` shorthand to exact bytes and remove “license not stated”.
- GlycanGT source archive record [10.5281/zenodo.18636040](https://doi.org/10.5281/zenodo.18636040): license **CC BY 4.0**, archive ZIP 7,688,791 bytes. This is the source-data archive, distinct from separately gated HF model files.
- SweetFold Zenodo data record has CC BY 4.0, while the **code repo has no stated code license**; distinguish them.

These license corrections do not alter the compute conclusion: GlycoBART’s reported 4×A5000/30 epochs and SweetFold’s multi-GPU Boltz fine-tuning are not established as under 4 GPU-hours on T4; GlycanGT’s full four-model checked-in recipe remains about 3.62M minibatches and is not a credible under-4h reproduction.
